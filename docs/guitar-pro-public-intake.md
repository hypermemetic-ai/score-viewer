## Converter `2146166`

The vendored package is score-converter `2146166`. `scripts/converter-package-identity.mjs` derives its identity from the packed archive and a clean converter checkout. A test reruns that derivation against the vendored archive. The converter now also admits keyboard, vocal, percussion and other tracks as `arrangement` results, up to 32 tracks. The viewer still reads only `fretted` guitar and bass parts. A track that inspection describes as another family is shown disabled in the chooser with a plain reason. A conversion of another family, or one without tuning, is refused with the same message. This description only withholds a track and never grants a family.

Exact cold replay needs the converter that prepared the retained source. If a descriptor names a different, well-formed converter archive, the part is treated as coming from an earlier converter. Such a part still opens through ordinary package admission and is not replayed. It gets no Guitar/Bass context, so its instrument name and sibling parts are unavailable, and a notice tells the player. A copied or forged descriptor can therefore only withhold authority. Importing the same original again is still refused as a "different retained edition".

The pinned ISO reader refuses this converter's guitar/bass MusicXML. On the authored fixtures it refuses the notation-staff `<staff-details>` (staff lines and capo 0) and `<tuplet>` notations. The earlier `aea081ed` output parsed. Guitar Pro import therefore needs ISO reader support before this package can ship. The end-to-end test is marked `todo` with that reason.
