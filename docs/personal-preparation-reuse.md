# Personal preparation reuse

Each viewer activation owns its `PersonalPresentationSession`, admitted package, member buffers and last displayed view. A bounded process-local pool can retain the shared rendering core across compatible reopenings. The identity captures the full literal source and effective baseline, rendering recipe, calculation context, layout and package meaning, plus hashes of copied archive member bytes. An archive digest claim alone cannot authorize a hit. Inputs are captured before asynchronous hashing; later mutations cannot alter an in-flight producer. A new activation captures its own current inputs.

The pool retains at most two ready cores and 64 MiB of conservatively counted source material, including the captured identity. This bounds retention accounting, not the complete JavaScript heap: shared private layout maps, scene structures and VM overhead are not measured heap allocations. An oversized core remains usable by its active facade but is not retained for unrelated reopenings. No shared rendering core is persisted to disk.

Core preparation and projection are serialized. A canceled caller cannot lend its incomplete producer or execution callbacks to another caller; failed or canceled core operations discard the ready entry and retry cold. A canceled queued caller does not invalidate an untouched ready core. Reopened views always use the current activation's package wrapper and member buffers, and resolve its current personal choices. Changed-system/page lists describe the shared core's previous projection and are never used to skip painting the current activation. Finger-only choices return the activation's admitted baseline.

Foreground callers can pass `ReadingExecution` to `warm` and `project`. Reviewed shared `warmAsync` and `projectAsync` capabilities receive that execution; the synchronous edit path remains available. The same optional execution reaches retained-recipe replay, calculated-edition cold admission and nested original-score transposition admission. Literal baseline page/seat hash checks, source/paint admission and cancellation-before-publication remain required. The compatibility seam can compile against the historical source pin; cooperative responsiveness depends on integrating the reviewed shared dependency that provides those APIs.

Focused tests cover identity invalidation, fresh wrappers, serialized concurrent access, canceled/failed retry, entry and material eviction, and an independently cold-rendered admitted hand-transfer fixture. These checks establish reuse and output correctness; they do not claim a native load-time measurement.
