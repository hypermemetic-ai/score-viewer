# Dual reading and manual practice UI

For new actually admitted dual-reading sources, the reader and Score Options share one keyboard picker named Notation, with ISO and TAB choices. Escape cancels a choice; Enter commits it and retains focus. The reader restores a genuine written bar/component anchor in the selected presentation rather than copying a page ordinal. Separate saved scale/page-group cursors share that anchor. Full-page reading and either notation remain available without a reference tempo. Entering Practice then asks for an explicit playing reference only if both the canonical reference and a separately saved choice for that exact source part are absent. Escape cancels without writes. The choice does not rewrite the score, and ISO/TAB share it.

Manual practice reuses the refined passage selector, Options navigation, numeric editor, display rotation, clock and full-repeat cue. It keeps all musical ink visible. Previous/Next turns overlapping four-bar source windows on request during playback or Free view; a five-bar leaf exposes both 1–4 and 2–5 without changing its five-bar loop. A repeat restores the first window only when its actual count-in starts. Done requires a completed loop and can be withdrawn after a notation switch; neither elapsed time nor connected piano MIDI creates measured progress. Both notations save one musical journal for that part. Library summaries follow that journal rather than the selected piano keyboard.

No independent TAB engraver or app clearance exemption is introduced.

The controller stops its owned transport before replacing notation, fences pending manual preparation, and serializes notation changes. Saved view state stays separate from the immutable admitted source/presentation graphs. Failed view writes retain the original archive, library pointer and last saved view. An unchanged dual-score reopen validates its existing personal journal and activates the admitted views without reinstalling the archive or randomizing a new piano journal pointer. The alias adapter uses the unchanged native managed-file bounds. Existing piano practice and physical controls retain their own controller and journals; both assessment modes use the same visible Practice Options markup.
