# Score transposition

Open a score, then open **Options** (O by default). **Score** is the first section, or follows **Practice** when practising. Transpose is measured in **steps**: positive raises every pitch, negative lowers it, and 0 restores the retained original. One step is the next adjacent chromatic pitch. The legal range depends on the score's highest and lowest sounding pitches; pitches never wrap or fold into another octave.

The numeric field uses the same controls as practice speed. Arrows browse Options. Enter edits the value; type a whole number or use Up/Down, then Enter commits or Escape cancels. The stacked mouse chevrons are outside keyboard navigation. An invalid draft leaves the score unchanged. During preparation, Cancel keeps the current edition and value. The new value becomes selected only after complete admission and additive durable installation.

Reading, practice and performance assessment use the same selected pitches. The physical piano still sounds the incoming MIDI pitches: this setting changes the score, rather than the piano's global input. Original reference MIDI remains an original-source attachment; the viewer has no score-MIDI playback feature.

Each genuinely new pitch edition has newly calculated fingers and physical contacts, with its own personal corrections, practice and performance evidence. Achieving the original pitch does not count as achieving the shifted exercise. Original archives, corrections, calculation history and journals remain retained. Selecting a retained pitch edition recovers its own saved choices and progress. Selecting 0 restores the exact retained untransposed archive for the selected keyboard, rather than calculating the original again.

When changing pitch from practice, the old session is paused and its save queue is settled before installation. The new session keeps the passage range, grouping structure, legacy partition, browsing choice and applicable Free view window. A fresh edition inherits practice preferences, including starting speed, increase, target and speed lock, but begins at starting speed without earned progress. A retained edition keeps its own saved preferences and progress. It starts paused with new pitch obligations and without inherited completion eligibility. Old queued MIDI events cannot advance its assessment. Opening Options and cancelling an edit retains the existing session.

The selected offset belongs to the original score collection and survives reopening and keyboard changes. Archives for each offset and keyboard are retained independently. If a keyboard is first added while transposed and has no original presentation, the ordinary worker first prepares an admitted untransposed companion while preserving the already available original pages and journals. The derived view and its zero companion are staged together; neither intermediate result changes the current selection if preparation fails. Returning to 0 preserves the user's keyboard preference.

The target practice journal and grouping are validated before changing the selected archive. Retained grouping has priority when old navigation joins cross a differently joined target passage. Compatible joins are kept; if the exact previous range is unavailable, practice asks the player to choose a passage. This preserves the retained journal rather than inventing overlapping practice evidence.

A shared transposed archive contains its exact untransposed baseline once. Import stages that baseline additively so 0 also works offline on the receiving computer. Earlier editions and generated versions retain their actual admitted offset; importing an original update while a nonzero offset is selected asks the player to restore 0 first instead of silently resetting the selection.

The archive/worker authority and replay rules are documented in [score-transposition-authority.md](score-transposition-authority.md). Source tests and browser inspection establish source behavior; native recipient inspection and physical playing remain separate acceptance steps.

Validation includes complete public pages and supported four-measure strips crossing original page/system boundaries, with ties and slurs on both keyboards. Existing preview refusals were also observed unchanged at original pitch and +1: source systems with only one or two measures can lack an ordinary separator template after cropping, and a three-component written-hold control refuses incompatible relation sides. Their complete pages remain admitted. Transposition does not bypass these existing checks; those preview cases need separate rendering repairs.
