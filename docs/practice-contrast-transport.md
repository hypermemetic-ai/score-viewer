# Source-faithful paired contrast playback

A contrast exercise owns two real source clips and one attainment pattern. The piano and manual views construct each active session with `practiceClipChunk(owner, index)`. There is no continuous range covering the intervening measures. Reading, preview and grading use only that clip's source owners; a carry owner keeps its real earlier attack and release.

`PracticeContrastCycle` captures A's working rate and assessment. A advances to B without a completion claim. B completing the same live cycle grants the paired exercise's own claim; originals and connections receive no credit. Pausing, errors, selection, closing or a changed piano connection cancel the cycle. Resume starts A. Each A/B re-entry uses a fresh count-in and exact source clock. Contrast transport never pre-arms a speculative repeat. Desired speed changes wait until the next A cycle.

`practiceClipPlan` filters piano gestures and attacks at the source excerpt, including earlier sounding owners. `practiceClipCompletionTick` extends only actual included hold obligations. The extra time grades no new attacks and displays no later music. Manual sessions use the equivalent admitted owner releases. Carry preparation shows the real earlier owners, rather than a whole leading passage. Personal hand or finger changes retain earned credit.

`renderPracticeClip(package, plan, clip, mount)` returns the shared composed passage including `.svg`. It crops actual source columns and retains real source pitch, note spacing, beam fragments and tie components. `manualPassageClipScene(package, bars, clip)` returns `.svg` as a string for admitted ISO/TAB scenes. A selector renders A and B separately. Exclusion changes assessment membership, preserves row positions and earned evidence, and saves through the existing views.

The optional pulse-grid `sourceExcerpt` binds exact endpoints to original first/last source-bar bounds and phases. Both TypeScript and Rust independently validate it. Ordinary grids retain their strict legacy complete-bar rules. Count-in phase and rational source pulses are preserved; no padded clicks or later source attacks are invented. The clock includes an explicitly admitted hold tail where required.

Verification: focused unit tests exercise complete-cycle acceptance, cancellation during B startup, captured versus queued rates, exact partial-bar clocks and ISO/TAB source component crops. `scripts/check-contrast-lifecycle.mjs` runs the production views in isolated Chromium using controlled clocks and musical MIDI input, both No14 piano layouts, catalog/exclusion/preview geometry, and an authored manual source. Temporary browser/server processes close in `finally`. The native pure-source harness covers the paired TS/Rust protocol and lifecycle; it is not native installation, physical piano or human musical acceptance.
