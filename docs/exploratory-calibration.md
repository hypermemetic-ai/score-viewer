# Exploratory hand calibration

The pilot imports the supported root API of fingering-calculator revision `e325912d00efaef887738f4fb0f94a2495d58577`. It collects one selected hand at a central reference chosen on the existing instrument: 208 Jankó judgments in eight blocks, or 52 conventional judgments per reference pitch, with an optional second reference for 104. The two pairs are thumb–index and index–middle. Both fingers take the anchor role; targets extend through thirteen decimal semitone steps on the usual side, mirrored for the left hand. Jankó tests both physical anchor and target levels. Missing target coverage refuses the plan before collection.

Editable profile defaults cover actual MIDI pitches 21–108 and remain explicitly **nominal**, not measurements. Jankó starts with 9 mm usable width, 0.5 mm side margins and a 5 mm opposite-parity body gap, with declared depths, heights and key travel. Conventional dimensions are also declared estimates. All dimensions enter the physical geometry identity, so an edit cannot silently transfer earlier observations onto different geometry. Geometry and the seating/setup reference are frozen within each session. The session records player/setup identity and body midline; it invents no endpoints, measured wrist pose or contact depth.

The separate file `calibration-pilot-v1.json` contains a `viewer-calibration-pilot-v1` envelope with `playerId`, `activeSessionId` and all `sessions`. Each entry retains its complete canonical plan, provenance, block setups, observations and retractions. Core pilot validation admits every entry; duplicate IDs, foreign player identity and unsupported versions are refused. Invalid original bytes stay read-only and export losslessly as base64 with the filename, byte count and error. Reading or exporting never replaces them. Legacy `calibration.json`, span profile selection, source/calculated fingers, personal corrections and practice journals remain separate.

Each block needs a saved setup acknowledgment. Keep the wrist/direction instruction next to grades; the player reports combined pressing followed by held-anchor tapping at a self-selected pace. Grades 0–3 attest both patterns; grade 4 can have no performed patterns and does not remove later targets. These categories are ordinal. Finite completion counts unique targets with an active judgment; correction appends history, and retraction reveals an earlier grade or restores unknown. Completion means this prescribed round is complete, not that a fitted hand model or generalized reach restriction has been established.

`PilotController` owns one persistent shared input router, accepted state and a synchronous save gate. Start, setup, rating, navigation, correction, session selection and undo write the candidate archive before publishing it. Another mutation while a write is pending is refused. A save error preserves the accepted target/evidence and reports a recoverable error. Optional rating notes remain on failure. UI subscribers receive detached snapshots; note keystrokes do not cause rerendering. Button grades are direct manual commands and never synthesize piano notes or key-up events.

The shared router at the pinned revision does not remember ignored test-note downs. The Viewer therefore retains transient logical MIDI down identities across trial changes, setup gates and pending writes. A repeated positive note-on stays ignored until note-off or velocity-zero note-on. Eligible held controls and raw Digit/Numpad keys must release before another command; held test/anchor notes do not block manual grading. Both input paths remain available concurrently. These identities and normal MIDI timestamps never enter saved evidence. Duplicate physical Jankó copies with the same device/channel/pitch follow logical MIDI note-on/off semantics; the stream cannot establish separate physical-key holds.

Main integration owns device source/generation, focus, calibration activation-clock freshness and native channel conversion from 1–16 to 0–15. It dispatches calibration before practice observers while retaining the instrument's normal sound path. `break()` clears readiness and input edges; `reset()` clears edges only. Every reset increments the runtime-only `inputGeneration` token. Main refreshes its activation floor on token changes, including a successful same-session resume; a rejected or pending resume does not advance the token, and ordinary ratings leave it unchanged. The token never enters saved evidence. Disconnect/focus/session lifecycle resets must not be inferred from playing telemetry. Reopening uses the core resume operation so setup is pending again, even if readiness was persisted before closing.

An already-started write may finish after a break or disposal. Its durable evidence is retained, runtime readiness stays cleared, and disposed listeners receive no later callback. Before loading/reopening a new controller, wait behind its pending writes and then read the file afresh. Main uses its ordered persistence queue for this barrier; callers managing a controller directly can await `flush()`. This prevents an older in-flight write from overwriting a new controller's session or a stale cached load from hiding the completed evidence.

Focused tests exercise canonical counts/identity, invalid-byte recovery, delayed and failed saves, revisiting/undo, full-round completion, input interleaving, held-note reclassification, closure and flush. They provide software evidence; they do not certify measured instrument geometry, human adherence to setup, physical MIDI/audio timing or useful fitted fingering predictions. Production UI/native observation is owned by the integration acceptance checks.
