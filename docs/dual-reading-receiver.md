# Dual musical reading receiver

The source checkpoint uses the independently reviewed, still unmerged ISO PR348 head `80b38442e3d987cf22add926fe85fed1b8405bc2` in this isolated branch. This is a provisional source dependency, not a selected native build or installed capability.

`instrument-reading-package-v2` stores one canonical selected source part and complete written-component ledger, with independent ISO and TAB pages, owners, scenes and geometry evidence. Its default manifest pages are ISO. The receiver runs the public `prepareFrettedViews` once and compares both complete results exactly before exposing either view. Existing compressed, member, expanded and file-count limits apply to the combined archive; each view remains limited to 500 pages. Both page sets pass the existing passive SVG gate. Descriptor v1 continues its literal historical preparation and byte identity.

`prepareDualReadingPackage` captures an owned input graph before hashing. The receiving path binds literal source event IDs, real tuning, rests, tied continuations and relation endpoints. A generic source has Unknown instrument family. Neither score labels, string count nor program numbers establish Guitar/Bass authority. The separate Guitar Pro path must replay retained original bytes through the public converter host, compare the final report/XML/selected part binding and then project the admitted source. A missing public host refuses; no saved hash or certificate replaces that replay.

`selectReadingNotation` requires the actual receiving realm's successful dual replay. The receiver freezes its complete source, manifest and dual content, and the private registry requires their exact admitted identities. Selection reads the private immutable record rather than caller serializers or mutable presentation data. Its ephemeral admission is never serialized. Selection changes the displayed pages/owners only; it does not rewrite the source, default manifest or archive. Publication retains both complete presentations.

The application's bounded `PackageAdmissionSession` copies wrappers and member buffers independently, while retaining that private cold replay's immutable musical source and prepared dual scenes. It does not register a deserialized scene or caller clone. This lets both cold and warm application reads use the source-owned projector without another replay or a persisted certificate; piano copy behavior remains unchanged.

`planManualPractice` consumes the complete source-written ledger for new dual content and retains declared derived-head/silence provenance for historical reading content. ISO and TAB produce the same plan and musical revision. `ManualReadingContext` owns one immutable source graph, one manual journal, separate notation cursors and a source-bar/component anchor. A notation change pauses its session before geometry replacement. Distinct part identities retain distinct evidence. No connected piano can create physical assessment or measured success for these source owners.

`ManualPracticeTransport` uses the existing `PracticeClock`, source pulse grids and full musical repeat protocol. It pre-arms the next full source-bar cue, adopts its owned receipt and uses the existing whole-bar fallback when pre-arming is refused. An unconfirmed acknowledgement at score entry pauses rather than playing a second partial cue. Cancelling or pausing fences asynchronous completion; a closed transport cannot start, re-arm or notify through a stale continuation. Manual elapsed loops enable reversible Done without writing measured bests.

This checkpoint does not expose manual UI, joined passage geometry, GP browser import or an instrument-family selector. Safe joined curves require the additional source-owned per-primitive inventory and endpoint attachment rules now under implementation. Historical neutral descriptor v1 manual UI remains pending; the new generic dual source supports manual ISO independently of which notation is selected. Existing piano practice and journals are unchanged. Browser visual/keyboard/manual acceptance, the final merged dependency and native delivery remain later gates in the active OpenSpec change.
