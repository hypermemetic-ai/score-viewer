# Optional native piano validation

The feature is being implemented through `add-optional-native-piano`. Source observations, the admitted cache, native packages and physical musical acceptance are separate evidence. The samples remain outside Git and the application bundle.

The approved original archive is 1,658,825,437 bytes with SHA256 `03d9a02da210ea0f5968ead11c8e764b3ddde1ea0cba5a0432e1f094905cbb35`. The unchanged Recommended live SFZ has SHA256 `6567611a435eb3503b5425f13c1092de4abec32fa237c6cf7f0467949ec729ee`. Admission retains all 716 original files and both README/license notices. A canonical sorted path/bytes/SHA256 fingerprint, `417f2d4c3f872fc2595ff6090009ef899981d1ac631b16cbb64fb083c7d5befc`, anchors the per-file marker. The live SFZ's 641 unique sample paths and all other original SFZ closures resolve inside the bank. Authored WAV headers and sample content remain unchanged.

The bank core snapshots and hashes the selected ZIP, bounds metadata and disk requirements, rejects unsafe paths/types/collisions, streams CRC/hash extraction and atomically publishes a complete version directory/current pointer. Failure/cancel removes only its staging/new unpublished directory and leaves the prior bank intact. The native adapter performs this work off the UI/audio callback; Options closure does not cancel it. Startup cache verification is cached once. Piano-off startup does not initiate verification, allocate a sampler or load samples; enable always requires admitted readiness.

Nine generated-archive tests passed for valid publication/offline verification/notices, unsafe paths, symlink/member-size admission, case duplicates/file ancestors, CRC failure, SFZ escape/missing/include refusal, cancellation/disk failure, changed ZIP/corrupt cache and modified-marker refusal. Three frontend preference tests passed for old-preference defaults, exact valid saved values/readiness gating and independent invalid-piano refusal. Commands ran under `/home/qqp/.local/bin/qq-job`; the pure core harness used the working private Rust1.99 compiler because the installed Homebrew compiler currently lacks its expected LLVM22 library. No global toolchain changes were made.

A private Linux observation invoked the actual production core with the already acquired original ZIP, with no second Internet download. Debug admission took150.55seconds and debug offline verification41.31seconds. A separate optimized full-cache verification took1.159seconds with3500KiB peak process RSS. These are core-harness measurements, not installed Tauri/native-device performance. Receipts live under the private benchmark `acquisition-artifacts/installer-admission.json` and `installer-verification-release.json`; the admitted cache is under `installer-observation/`. The native file picker and physical audio were not observed by this harness.

The Windows driver experiment showed an Intel SST microphone tradeoff; that history is evidence, not product helper copy. Product help instead states possible microphone/manufacturer-feature loss and restoration. Enhancement guidance follows Microsoft's [sound troubleshooting instructions](https://support.microsoft.com/en-US/Windows/Hardware/Audio/fix-sound-or-audio-problems-in-windows); optional compatible HD Audio guidance follows [Microsoft's low-latency audio documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/low-latency-audio). No driver changes are performed by the application.
