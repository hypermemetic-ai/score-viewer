# Manual musical practice foundation

The neutral planning, clock, window and saved-state APIs now serve the real browser's new dual-reading controller. An actually admitted descriptor-v2 source can be read in ISO or TAB, and enters manual practice with its canonical performance reference or a separately and explicitly chosen per-part playing reference. Clockless dual reading stays available; choosing Practice opens the shared tempo chooser when needed. Guitar Pro intake and admitted Bass/Guitar selection are separate pending integration tasks in `support-fretted-manual-practice`; generic musical intake remains Unknown instrument. Historical neutral descriptor-v1 manual UI is still unavailable. Native delivery and physical instrumental acceptance are separate gates.

`PracticePassagePlan` contains the existing source bars, musical meter/reference tempo, passage hierarchy and progress fields. `PracticePlan` remains its piano refinement with genuine MIDI attacks and hand gestures. Existing piano plans, patterns and saved filenames keep their original meaning.

`planManualPractice(package, partition, fallbackReference?)` accepts strictly admitted version-3 ISO reading content with complete source bars, ownership and written appearances. It captures the consumed score, descriptor, owners, scenes, pages and seats in one owned snapshot before awaiting its digest. A caller changing the source while hashing settles cannot change clocks or source identity under that digest; caller data remains untouched. The optional reference is captured in that same snapshot. A canonical source reference is authoritative even when a fallback is supplied; a malformed canonical reference is never replaced by that fallback. Its result includes pitched or explicitly unpitched musical owners and written components, not hands, seats or MIDI contacts. Source rests remain rests; source spacers remain spacers. Missing or contradictory owner clocks, tied components, scene locations or silence identities refuse. Grace timing remains unavailable rather than being guessed.

Historical reading appearances use `retained-reading-head-v1` provenance. A generated component ID describes an admitted owner and written clock, not a source event identity lost by an older tie projection. New TAB preparation requires the independently retained complete source-written ledger and tuning; the historical fallback cannot grant that authority.

Manual progress is bound to a versioned digest of the selected real part, partition and canonical source facts. Display title/composer, reading policy, pagination and derived stem direction are excluded; other source facts, including unknown additions, remain bound. The additive filename is `practice-manual-v1-<musical digest>.json`. `readManualPractice` validates its source/part wrapper and rejects measured piano success or preparation evidence. It neither aliases nor migrates existing piano journals.

`practiceAssessment` selects `manual` or `piano-midi` from score capability and actual piano availability. A connected piano cannot grant assessment to a neutral score. `ManualPracticeSession` has no MIDI matcher, contact state or automatic note retirement. Completing a musical loop enables the existing reversible Done claim; elapsed time alone writes no attainment. Include manual continues to determine whether those claims contribute to displayed progress.

Manual windows contain up to four consecutive source bars with two-bar steps and a bounded final tail. Previous/Next changes only the window, including while playing. It preserves the loop clock, tempo, musical pulse grid, owners and progress. A future-armed repeat retains the current window until its actual count-in starts, when the first window is restored once. The session consumes the same validated source pulse grid and repeat planning as piano practice. Working-speed increases are predicted for audio pre-arming and consumed at an explicit loop boundary.

The source tests use authored scores prepared and cold-admitted by the real ISO reading engine. They cover independent voices, dead notes, rests/spacers, ties, five-bar and twelve-bar windows, repeat timing, part/partition isolation, reversible claims and connected-piano isolation. The production browser checker additionally exercises notation pickers, Options, source anchors, fresh reopening, a failed view write, full-ink manual loops, long joined window keys, repeat reset and rotated Free view. Native compositor, physical instrumental performance and genuine Guitar Pro intake remain separate acceptance gates.

A source without a canonical reference retains its original musical digest for reading/view identity. Its explicit fallback reference is validated and included in a distinct practice revision, so an old completion is not reinterpreted at a different clock. A `manual-reference-context-v1` envelope binds that reference to the exact part and source-musical revision under a native-valid `practice-<digest>.json` filename. Missing or differently bound saved choices cannot borrow another part’s tempo. Original score/archive bytes and legacy piano journals remain unchanged. Automated private diagnostic references and completion fixtures are classified separately from player choices or measured performance.
