# Manual musical practice foundation

This source checkpoint provides the neutral planning, clock, window and saved-state APIs for an admitted musical reading score. Reader controls, source-owned passage scenes, TAB preparation and Guitar Pro intake are subsequent integration tasks in `support-fretted-manual-practice`. The current application still opens practice through its existing piano controller; this checkpoint alone does not deliver usable Bass/Guitar practice or TAB.

`PracticePassagePlan` contains the existing source bars, musical meter/reference tempo, passage hierarchy and progress fields. `PracticePlan` remains its piano refinement with genuine MIDI attacks and hand gestures. Existing piano plans, patterns and saved filenames keep their original meaning.

`planManualPractice(package, partition)` accepts strictly admitted version-3 ISO reading content with complete source bars, ownership and written appearances. Its result includes pitched or explicitly unpitched musical owners and written components, not hands, seats or MIDI contacts. Source rests remain rests; source spacers remain spacers. Missing or contradictory owner clocks, tied components, scene locations or silence identities refuse. Grace timing remains unavailable rather than being guessed.

Historical reading appearances use `retained-reading-head-v1` provenance. A generated component ID describes an admitted owner and written clock, not a source event identity lost by an older tie projection. New TAB preparation requires the independently retained complete source-written ledger and tuning; the historical fallback cannot grant that authority.

Manual progress is bound to a versioned digest of the selected real part, partition and canonical source facts. Display title/composer, reading policy, pagination and derived stem direction are excluded; other source facts, including unknown additions, remain bound. The additive filename is `practice-manual-v1-<musical digest>.json`. `readManualPractice` validates its source/part wrapper and rejects measured piano success or preparation evidence. It neither aliases nor migrates existing piano journals.

`practiceAssessment` selects `manual` or `piano-midi` from score capability and actual piano availability. A connected piano cannot grant assessment to a neutral score. `ManualPracticeSession` has no MIDI matcher, contact state or automatic note retirement. Completing a musical loop enables the existing reversible Done claim; elapsed time alone writes no attainment. Include manual continues to determine whether those claims contribute to displayed progress.

Manual windows contain up to four consecutive source bars with two-bar steps and a bounded final tail. Previous/Next changes only the window, including while playing. It preserves the loop clock, tempo, musical pulse grid, owners and progress. A future-armed repeat retains the current window until its actual count-in starts, when the first window is restored once. The session consumes the same validated source pulse grid and repeat planning as piano practice. Working-speed increases are predicted for audio pre-arming and consumed at an explicit loop boundary.

The source tests use authored scores prepared and cold-admitted by the real ISO reading engine. They cover independent voices, dead notes, rests/spacers, ties, five-bar and twelve-bar windows, repeat timing, part/partition isolation, reversible claims and connected-piano isolation. Browser UI, native compositor, physical instrumental performance and genuine Guitar Pro intake remain separate acceptance gates.
