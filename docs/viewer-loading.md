# Viewer readiness

Startup and every foreground score operation (import, opening, re-engraving a saved edition, switching keyboard, transposition, restoring an earlier edition) use one loading surface, `src/viewer-loading.ts`. It names what the player asked for and the score, then lists the operation's steps in musical terms: finished steps are ticked, the current one turns, later ones wait, and steps the flow skips are dropped. The current step shows the engine's own stage (spacing the measures into systems, arranging the systems on each page, drawing page N, checking that every marking fits, placing the note labels, drawing slurs and ties, writing the tablature). Startup counts scores read for the library; it is the only determinate bar, because no other work reports a total. The running mark animates by transform only, so it keeps moving while the engine holds the page for a long synchronous step. The surface sits on black for the fullscreen viewer and respects reduced motion.

Startup shows the same surface while the library, settings, saved fingering choices, input listeners, practice summaries and enabled piano sound become ready. A sound failure is visible and permits use without changing saved sound preferences; a library failure keeps the files, says so and offers Close Viewer. Background library refreshes show a compact status after 120 milliseconds and yield priority when a foreground score operation starts.

Cancel (Esc) is offered while preparation is owned, with one sentence saying what it leaves (the library, the current score or the current keyboard as it was). Once the durable save begins, Cancel is disabled and the note says the remaining part can't be cancelled. When a transposition or earlier-edition restore has already saved, the opening that follows keeps Cancel disabled. Canceled or superseded preparation cannot replace the previous score. A failure the player did not ask for keeps the surface open, marks the step that stopped, shows the message and replaces Cancel with a focused Close; an operation started from Options instead returns to Options with the message as a notice. Each step's state is spoken with it for screen readers, and the status line announces the current step. An elapsed clock appears after three seconds; the surface never estimates remaining time, and no stage has a time limit.

The derived library cache and captured personal-preparation pool are separate from scores and earned practice journals. Their input bindings and retention limits are documented alongside their implementation. Cached summaries do not supply practice state, and private rendering authority is never restored from serialized cache data.

Performance reports distinguish cold work, same-process reuse and a new-process restart. Cooperative scheduling allows feedback and cancellation between supported steps; it cannot preempt an individual synchronous step. The existing 100-millisecond visible-edit tuning goal and accepted editing trade-off remain separate from startup/loading measurements.

An ordinary retained open preserves its existing package and personal-journal pointers when the prepared archive is byte-for-byte identical and belongs to the selected collection. Retained reading, ready and editable states all use this path; changed bytes continue through the existing validated installation path. Opening the score still admits current bytes and loads current choices.
