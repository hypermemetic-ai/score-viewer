# package-admission Specification

## Purpose
Preserve independent literal score and rendering authority while avoiding redundant work on exactly identical admitted bytes within a bounded runtime realm.

## Requirements

### Requirement: Cold admission remains independent
The viewer SHALL fully validate archive bytes, actual source replay, geometry, coverage, receipts and fonts on default cold import and each independent receiving realm. Runtime reuse SHALL NOT accept a worker or persisted certificate as this authority.

#### Scenario: New worker output
- **WHEN** a calculation worker returns an internally consistent prepared archive
- **THEN** its receiving realm cold-admits the actual returned bytes before request binding or installation

### Requirement: Bounded private reuse
A session SHALL snapshot exact bytes and effective admission options before awaiting, keep canonical graphs private, check current fonts on reuse and return independent clones with companion registrations. It SHALL bound retention and distinct cold producers, coalesce exact concurrent misses and invalidate cleared in-flight retention.

#### Scenario: Caller mutation
- **WHEN** caller input, returned files, semantics, companions or options are mutated after admission starts
- **THEN** later exact reuse preserves canonical admitted content and altered input receives independent validation

#### Scenario: Budget or font refusal
- **WHEN** an entry exceeds the material budget or font authority becomes ambiguous
- **THEN** it is not reusable as valid authority and the budget or font refusal is observable without altering source bytes

#### Scenario: Superseded library refresh
- **WHEN** a newer background refresh requests different bytes while an old cold producer is active
- **THEN** it waits for the single producer and rechecks generation/context before admission, while stale refreshes publish nothing

### Requirement: Retained reading preserves request policy
Direct retained reading SHALL use the private app-reader realm's actual cold admission of exact bytes/options, the existing readiness policy and independent new-request binding. The bounded reader session MAY survive exact repeated opens, SHALL recheck applicable fonts on every reuse and SHALL clear on disposal. Library and fresh Worker receiving sessions SHALL remain separate. Changed tempo/pitch, forced preparation or missing companions SHALL retain Worker execution, original refusal rules and strict receiving validation.

#### Scenario: Exact saved keyboard
- **WHEN** a saved presentation is opened without changing pitch, tempo, policy, personal state or layer
- **THEN** the viewer avoids a redundant calculation worker while preserving identical archive members and request checks

### Requirement: Ephemeral head evidence is exact
The viewer SHALL record tiny head IDs only after complete actual admission, bind exact semantic/page/seat/recipe state and return copied IDs. Unknown or mutated objects SHALL use the existing strict replay fallback. No archive or public caller SHALL attach this evidence.

#### Scenario: Coincident or mutated head
- **WHEN** seats represent coincident source heads or an admitted page/owner tuple changes
- **THEN** complete original head identities are preserved or reuse is refused without weakening matching semantics

### Requirement: Performance evidence distinguishes cold and warm
The change SHALL report actual first import, repeated open, keyboard switching, library refresh, worker reception, main-thread stalls and memory using fixed fixtures and source pins. It SHALL preserve original user data and explicitly state remaining cold limits.

#### Scenario: Reported speedup
- **WHEN** a warm operation improves substantially
- **THEN** its measured baseline, scope, cold counterpart and authority controls accompany the claim
