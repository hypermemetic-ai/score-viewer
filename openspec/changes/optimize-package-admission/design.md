## Context

Strict cold import validates literal archive members, hashes, source/owners, actual complete engraving, geometry, receipts and font authority. Measurements attribute most delay to real source replay, rather than unzip, hashing or XML parsing. A baseline Chromium readiness worker took 11.9–12.7 seconds: about 4.1–4.5 seconds in worker initialization/computation and 7.8–8.2 seconds in repeated receiving validation. The actual main open took 22.33 seconds for the original Zelda edition. These are fixture/host observations, not universal targets.

## Goals / Non-Goals

Reduce duplicate work on exact immutable data in one compiled realm while preserving every required independent validation. Measure actual cold and warm outcomes and memory. Do not change musical algorithms, tolerances, fonts, archived ink, source authority, saved progress or worker calculation admission. No tenfold claim without measured evidence.

## Decisions

### Runtime-owned admission

`importPackage` remains strict and cold by default. A session snapshots bytes and effective options before its first await. Its canonical graph, all companion registrations and transposition originals never escape. Every caller receives a fresh deep clone and fresh private companion registration. Exact equality resolves byte-key collisions; permission options cannot share authority. Selection among fully admitted companions does not change admission authority. Current actual annotation font authority is checked on every copy.

The session keeps at most two entries and 64 MiB of archive/member/unique-graph material, evicts least-recently-used entries, coalesces concurrent exact misses and explicitly clears on operation disposal. Only one distinct cold producer may run; additional distinct misses receive a busy refusal rather than starting unbounded uncached work. An active producer retains its slot through clear, and the new generation cannot borrow it or be repopulated by it. Sequential library summaries need no queue. Material accounting is a policy for represented content, not exact VM heap measurement. Above-budget packages still receive cold admission and independent copies but are not retained. Mutation of caller bytes, request fields, output graphs or files cannot alter canonical evidence.

### Receiving and retained reading

Each worker completion creates a fresh reader-realm session and fully cold-admits returned bytes before validation. Request binding can reuse only exact bytes and options admitted by that session. New requests independently check source, hands, tempo, transposition, policy, personal state and layer; no request result is cached.

Each open/import/keyboard operation creates a fresh session. Exact saved-layout reading with unchanged pitch/tempo, no force and no missing companion runs the existing readiness policy and independent request binding after that session's actual cold admission. Genuine calculation retains the real worker and strict reader admission. Cancellation invalidates in-flight retention and retains prior bytes. Library summary reuse still rereads current saved progress; it never caches practice results as score authority.

### Separate written-head ledger contract

Actual source replay may return tiny head IDs for exact seat/page/system/x/baseline/font-size/digit/sorted-owner tuples, including coincident heads. Viewer records them in a private WeakMap only after complete literal/geometry/coverage/receipt admission. The accessor validates current semantics/pages/seats/recipe and returns copies. Unknown or mutated packages use the existing exact replay fallback. Canonical clone transfer requires private exact registration. Every receiving realm derives its own ledger. Nothing is serialized or publicly attachable. This contract is separately reviewed from the pure rest reuse.

### Remaining cold stalls

Cold engraving contains long synchronous layout/scene work. An arbitrary `await` before it merely delays the same stall. A bounded cooperative strategy needs explicit pure-layout/scene yield boundaries or off-main computation with independent receiving verification; it requires a concrete reviewed proposal before source changes. This task records remaining first-cold stall rather than treating cache hits as solving it.

## Risks / Trade-offs

Cloning adds bounded copy cost and memory; budget/eviction measurements must accompany warm timing. Full source replay remains required for cold bytes, new realms and altered options. Font authority can become unavailable after a cache fill and must refuse reuse. Context generation and cancellation must prevent stale library or preparation results. Head-ledger identity must preserve coincident-head semantics and refuse any mutation.

## Validation

Unit controls cover mutation, same-size byte collisions, options, companions, concurrent misses, budgets and cancellation. Real browser controls cover current font ambiguity, real worker calculation/refusal, first import, second open and keyboard changes. All four retained Zelda editions, public No14 and the 10-page bass archive preserve literal members and actual receipt/policy/geometry results. Original journals/library/progress are read-only and hash-checked. Heavy jobs use qq-job; owned browser storage/servers are disposed.

## Open Questions

The remaining cooperative-yield mechanism is investigation only until a concrete proposal is accepted. It does not waive strict cold admission or block independently useful duplicate-work fixes.
