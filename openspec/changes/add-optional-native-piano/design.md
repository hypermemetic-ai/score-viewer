## Download and future transport

Download piano invokes a native no-argument command that downloads the fixed V6.2a archive from archive.org (the author's page links it; its other hosts are share pages, not files). It runs the system curl (`/usr/bin/curl` on macOS, `System32\curl.exe` on Windows without a console window), HTTPS only including redirects, resuming with `--continue-at -`, with a stall limit and up to four attempts per press. A partial download is kept in the cache root for the next press after a network failure and removed on cancel, a refused server answer or a size beyond the archive. A HEAD request first checks the server's size and ETag (or Last-Modified): a different size stops with a plain "the piano file online has changed" pointing to Install from a file…, a different ETag discards the partial before resuming (archive.org re-uploaded the item on 2026-10-13 and 2026-10-15), and curl gets `--max-filesize`. A refused resume discards the partial and restarts once. The finished `.part` is checked in place and enters the same admission as a chosen ZIP, so only one archive copy uses disk, and is deleted only after publication. One viewer at a time holds `piano.lock`; curl inherits it and dies with the viewer (process-group watcher on macOS, kill-on-close Job Object on Windows). Quitting keeps the partial; stale `pending-*` stages are removed or salvaged on the next press. Windows curl receives only ASCII arguments, with the piano folder as its working directory. Install from a file… picks a local ZIP for offline use. A successful press switches the piano on; MIDI stays an explicit choice. Cloudflare provisioning and properly authored 44.1 kHz conversion remain deferred.
