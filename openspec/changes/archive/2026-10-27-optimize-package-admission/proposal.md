## Why

Opening a retained edition of a private score takes about 22 seconds in the actual viewer. Each strict cold admission costs roughly 5–7 seconds, and one open repeats that admission in preparation, worker reception and request binding. A measured performance audit and substantial improvements are needed without weakening score authority.

## What Changes

- Reuse one pure rest scene per actual source-layout coverage pass (independently reviewed ISO PR342).
- Reuse final read-only scenes within a single phase-owned presentation call, preserving distinct score contexts and mutation/refusal boundaries (independently reviewed ISO PR344).
- Add a bounded, runtime-private package admission session with exact-byte keys and independent returned copies.
- Reuse receiving-realm admission only after that realm has fully cold-admitted worker output.
- Read unchanged retained presentations through the existing policy/personal/layer service, without launching a redundant calculation worker.
- Reuse tiny written-head IDs derived by actual strict replay, with exact mutation checks and the existing strict fallback.
- Show loading/cancellation and yield at completed operation-phase boundaries; measure actual first import, repeated opens, keyboard switching and library summaries while retaining synchronous strict cold replay.

## Capabilities

### New Capabilities

- `package-admission`: strict score authority and bounded in-process reuse across viewer operations.

### Modified Capabilities

None. Frozen pages, musical calculation and rendering policies remain unchanged.

## Impact

Viewer package/readiness/request admission, library summaries and narrowly coordinated main operation hooks; separate ISO score-presentation optimization and ephemeral result contract. No persisted certificates, native audio, desktop actions, release dispatch, authentication or workflow changes. Private uploaded scores and measurements remain outside Git.
