# Design

## Context

See proposal.md for motivation. Current `PracticeView` uses the bounded exercise catalog: originals, independent adjacent pairs and contrast exercises. `PracticeBrowser.renderBounded` lists those exercises on the left and repeats their originals on the right. The older selector groups a range as completed when its leaves are attained but displays the range's separate achievement; `test/practice-browser.test.ts` explicitly permits the resulting 0% completed row.

`nextPracticePassage` uses lifetime attainment. The active controller calls it while predicting a repeat, completing an ordinary trial, and completing a contrast cycle. A controlled production-method reproduction on the Schumann 14 reference selected 1–4 at 18 BPM (10%): without old completion it predicts a 21.6 BPM repeat; with an old 180 BPM best it suppresses that repeat and selects 5–8. Both legacy and bounded partitions reproduce it. The prior research ran 54 existing passage/lifecycle/Reading tests successfully; they omitted this replay case and include an expectation for target-speed automatic progression that the user has now rejected.

## Goals / Non-Goals

**Goals:** Compact browsing derived from existing evidence; explicit group-versus-exercise selection; stable active exercise; concise existing visual vocabulary; preservation of musical repeat and persistence invariants.

**Non-Goals:** New long practice exercises, changed attainment/Total mathematics, forced breaks, break reminders, a new auto-advance option, a timing-engine rewrite or changes to the fingering integration plan.

## Decisions

### 1. Derive browsing groups without creating exercises

Build a presentation model from original sections in source order and their current displayed completion criterion. A group is a maximal consecutive run whose originals each meet the target; actual source adjacency, not musical resemblance, determines membership. Unfinished connections do not split a group. Include singleton completed runs. Groups contain original IDs and the existing eligible adjacent pairs; they have a separate identity and never become `PracticeChunk`, gain progress, enter the Total denominator or produce an unbounded score-rendering request.

One group row occupies one left-column slot under Completed. Incomplete originals appear below under Incomplete, retaining their existing own-progress/source-order sorting. Right-side contents for the selected group put unfinished adjacent-pair connections under Connections, followed by completed originals and completed connections under Completed. Preserve source ordering within each right-side category. Hide empty headings; do not add descriptions or counts by default.

Retain Contrasts as its existing descriptive category below the left-side section categories. Preserve access to associated adjacent connections through the right-side contents of their incomplete constituent section, including locked pairs with existing prerequisite feedback and pairs eligible through manual evidence hidden by the display filter. When selecting an incomplete original, keep it selected as the concrete exercise and show its preview/details; do not duplicate that original as a second list row. Actual completed connections remain available for repeat practice rather than disappearing from the catalog.

Alternative rejected: using joined exercises as groups preserves the false group percentage and accidentally makes a long grouping playable. Independent two-section connections remain the only joined exercises generated by current attainment.

### 2. Separate group focus from exercise selection

Represent the selector target explicitly as a group or a real exercise and track the active column independently. Group focus has no practice/Done/exclusion target. Right or Enter on a group enters its children without starting them; Left returns to the enclosing group. Up/Down navigate the current list, and Enter on an eligible concrete exercise starts exactly that exercise. Clicking a group reveals its contents; existing mouse activation for concrete exercises remains available.

Preserve a selected concrete exercise by stable ID when completion or Include manual changes the displayed grouping. A group merging or splitting must not select a different exercise. If an active concrete selection no longer belongs to a displayed completed group, locate it through its incomplete constituent or contrast category without duplicating artificial group rows. Initial recommendations can highlight a concrete exercise but cannot activate it.

Exclusions apply only to actual exercise IDs; excluding one does not complete a section, split a completed group or remove saved evidence. Include manual continues to affect displayed completion and grouping only, with checkbox focus and real prerequisite checks preserved. Maintain contextual list scrolling, existing footer Navigation/Enter Open hints, row rhythm, hidden scrollbars and shared kbd styling. Do not add the mockup's divider, explanatory footer or decorative arrows to the product.

### 3. Limit copy to descriptive categories

Use Completed and Incomplete on the left, Connections and Completed on the right, and the existing Contrasts category where relevant. These are headings once per category, not repeated row instructions. Rows primarily show source ranges and real exercise percentages. Group rows have no percentage. Do not use Learned regions, Sections to learn, Connections to practice, advice to practice a particular category, or a new explanation of grouping. Existing accessible roles and prerequisite messages still convey required semantics without adding visible prose.

### 4. Remove active automatic exercise progression

Keep `nextPracticePassage` only for passive selector suggestions and its existing pure recommendation consumers. Active continuation must use the selected exercise, not recommendations or a target-speed gate. There is no auto-advance setting and no special completed-replay branch.

In `predictedRepeatRate`, project the existing `passed` rate/evidence rules without asking whether another exercise is recommended. Remove recommendation identity checks from ordinary completion and prepared-repeat admission. Adopt an eligible prepared repeat for the same session; if it cannot start on time, pause that same session and keep the existing explicit Resume/count-in path. Remove the automatic successor/overview branch and delete `continueTrial` once its obsolete callers are removed.

For contrasts, keep the intentional A-to-B transition. After an accepted complete B, save with current generation/session guards and restart A of the same selected contrast at the normal next rate. Never select another exercise or return to overview automatically, including when every catalog exercise is complete.

Preserve `pendingCompletion`, `completionRevision`, `repeatAnchor`, `stopClock(preserveCompletion)` and delayed `repeatCompletion`: these protect same-exercise Done/undo, count-in replacement and native acknowledgements, not successor navigation. Preserve terminal-only repeat preparation, held-contact admission, immutable audible cue rate/grid, save errors, cancellation and pause/close generation checks.

`passed` retains historical best and normal increase-to-target behavior. At target, ordinary repeated success stays at target; keep-tempo and explicit queued/above-target settings retain their current rules. Historical completion, manual marks and equivalent-section evidence cannot redirect active selection. Unlocking a connection changes its availability only. A player can return to the selector, pause or take a break using existing controls; the change adds no automatic break or prompt.

## Risks / Trade-offs

- Group rows currently share exercise-shaped handlers → use a distinct selection type and test every activation/Done/exclusion entry point.
- Include manual or new attainment merges/splits groups → retain concrete identity and checkbox/focus context; never mutate evidence for layout.
- Current specs say every row has a percentage → explicitly narrow that promise to concrete exercises while preserving independent attainment and Total.
- Removing successor branches can damage repeat races → preserve the existing receipt/save/cancellation machinery and cover low-speed, target-speed and contrast repeats.
- Historical installed selector differs from current bounded source → implement the current catalog and test retained legacy helper paths where still callable; do not reintroduce recursive joins or claim today's installed behavior from a historical receipt.

## Migration Plan

No stored evidence or settings migration is needed. Land the grouping/selection projection and active-loop simplification with focused tests and docs, inspect the real viewer at ordinary/narrow/rotated layouts, then run the configured build/test checks and reviewed PR path. Native delivery follows the repository's separate package/admission path; do not interrupt the current practice session. Source rollback restores code without rewriting journals. Coordinate the still-open `introduce-reading-timed-practice` spec delta at later synchronization so its older generic selector-row wording does not overwrite the group distinction.
