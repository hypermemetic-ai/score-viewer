# Proposal

## Why

The operator reports disconnected measure fragments in passage selection and active practice, plus long-duration hollow stems left behind after their notes disappear. Schumann No. 14 practice was also unusable, prompting a separately completed Windows rollback; repairs now belong in the extracted viewer repository so the intended fixed-position practice can receive a usable visual and musical review.

## What Changes

- Compose selected consecutive measures into one continuous horizontal strip with aligned staff lines, correctly owned musical separators, and no independent crop gaps or horizontal scrollbar.
- Use the same passage composition rules in the leaf selection preview and active practice, while retaining fixed reading positions, existing slot replacement eligibility, and paused/unmeasured page controls.
- Project original source-owned ties and slurs into the joined passage using shared curve rules and verified note endpoints. Reusing clipped original-system fragments is insufficient at system joins or fixed-position padding; displayed relations must connect without moving their notes or rewriting stored pages.
- Fit an ordinary four-bar leaf across the available width efficiently, with substantial consistent outer breathing room so notation does not crowd the preview edge. Center both selector and active passage notation naturally, accounting for unused internal SVG/slot space rather than centering only its frame, while preserving stable active reading references. Keep large joined passages bounded to useful windows rather than compressing a whole work into a tiny preview.
- Bind all owned duration ink, including hollow stems and their white interiors, to the same visibility and Pause restoration as the associated notes. Handle supported glyph families and scores generically.
- Make the existing shared Options dialog available during passage selection and active practice, with a Practice section first and the full existing options below. Use Options consistently on buttons, the dialog, and the configurable binding entry, defaulting to O without overwriting saved assignments. Keep the existing persisted action identity compatible and retain the paused passage when closing Options.
- Remove visible individual measure numbers from practice notation; identify the selected range once outside the strip in selection and the active session header. Use one short Progress summary and one achieved-speed percentage per passage, with an Include manual checkbox beside Progress. Checked by default, it includes the highest measured or manual rate; unchecked, it displays measured rates only. Keep component and joined-run attainment independent and preserve stored evidence and automatic passage suggestions. Reserve three stable browser columns: compact passage ranges, compact original groups, and the selected group's whole-leaf preview. Anchor list percentages at the right and reserve width for the full score's measure-number digits. A long joined selection exposes its components without squeezing the preview or shrinking the whole work.
- Remove redundant incomplete-status and separate Best/Done wording from selector rows. Place small up/down chevrons vertically inside the numeric box's right edge with room for focus borders; center values in slightly narrower boxes and align the three settings boxes in one column. Keep `%` and the beat-unit marking outside the numeric box. Use compact `/min` consistently for visible absolute per-minute units while retaining spelled-out accessible names. Full-score Performance Tempo displays a percentage above its absolute Score reference; Practice Performance target remains absolute. Explain percentage speed controls consistently with their reference and describe Performance assessment in plain language. Set a fresh practice state's default increase per success to 1% of its target while preserving saved custom increases.
- Put selector Escape-to-Score guidance in compact bottom controls and remove its duplicate top-right exit label. Keep the selector guide and actions on one row when the available width permits it. Active practice identifies Escape-to-Passages, preserving the existing two-step return path and accessible mouse navigation. Keyboard navigation past a list edge snaps a useful new stretch into view with the previously selected edge row retained for context.
- Give existing shared tempo fields separate keyboard browse and edit modes. Up/Down navigates options; Enter edits the number, where Up/Down adjusts and typing replaces it; Enter commits and Escape cancels an unpersisted draft. Mouse chevrons remain available without becoming extra keyboard stops. Retain the established numeric admission and adjustment rules.
- Preserve joined/component attainment independence, timing and beat-aligned transitions, Done/Enter/pedal completion, queued speeds, shared rotation/input bindings, frozen package identity, and saved data.
- Require rendered lifecycle observations and visual inspection alongside meaningful geometry/ownership regression tests. Distinguish agreement with the fixed-position idea from acceptance of its implementation.

## Capabilities

### New Capabilities

- `practice-passage-display`: Continuous source-faithful practice passages, fixed reading references, readable selection previews, and complete note-ink visibility/restoration across supported keyboard presentations.

### Modified Capabilities

None. `practice-package` governs shared engraving preparation and frozen recipe compatibility; this change composes existing presentation ink and transient source-owned relation paths for application practice without rewriting prepared packages. `score-viewer-delivery` retains its separate paired native delivery contract.

## Impact

- Viewer application composition and lifecycle: `src/practice-view.ts`, `src/practice-browser.ts`, `src/practice-crop-fit.ts`, associated styles, and a scoped application passage/ownership helper if needed. `src/practice-window.ts` supplies the existing fixed-slot contract and should change only if integration requires a behavior-preserving adjustment.
- Shared input integration: `src/input.ts`, `src/control-bindings.ts`, `src/main.ts`, `src/options-navigation.ts`, and the existing Keys and pedals panel. Admit older saved binding dictionaries without rewriting existing assignments or reviving explicitly empty controls; share the configurable Options action between reader and practice and retain the library's Options entry. Share the dialog and existing option owners rather than duplicating settings or closing the practice session.
- Practice default and settings presentation: `src/practice.ts` changes only the fresh-state increase default; preserve exact retained increments, progress evidence, and existing progression/timing rules. Pure display helpers calculate achieved-rate percentages without the legacy preparation contribution, include or omit manual rates, and weight original leaves once for the selector summary. The filter changes displayed grouping/sorting without changing saved joins, eligibility, automatic suggestions, library aggregates or musical advancement. Shared manual-tempo field markup/styles align centered numeric boxes with vertical mouse chevrons and external units. The shared controller and narrow Practice/Performance adapters provide browse/edit drafts and Performance percentage conversion without changing stored numeric meaning, progression, or beat timing. Shared metronome display uses compact units without changing duration meaning. Selector summary, reserved component browsing, bottom guides, range context, and helper text remain application presentation changes.
- Tests: existing practice browser/window/session/lifecycle coverage, new meaningful rendered geometry/ownership regressions, and browser observations of actual preview and practice output. `src/practice-preview.ts` is the MIDI attack-preview matcher, not the passage-selection renderer; its matching behavior is preserved.
- Source baseline: merged viewer `11c1128a6140b9964aa7f2b4035de761ed7814fa`; shared notation/calculator remains pinned at `da93cf9e0359d861987fd76611b59b14b6aedb92`. No competing extraction, duplicated engine, package regeneration, permanent raw shared API, or dependency-pin change is proposed.
- The current Zelda package is private and absent from this repository. A generic real-engine long-note fixture can establish source regression evidence, while private Zelda observation remains an explicit acceptance check.
- This proposal does not port the ISO release lane, build or activate a replacement native package, or alter the restored Windows installation. Native delivery remains separately coordinated through the documented release seam.
