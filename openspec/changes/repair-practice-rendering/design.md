# Design

## Context

See `proposal.md` for the repair motivation and `specs/practice-passage-display/spec.md` for the behavior contract. This design spans both application display paths and their note-ownership adapter, so a design artifact is warranted.

The source inspected at merged viewer `11c1128a6140b9964aa7f2b4035de761ed7814fa` establishes these constraints:

- `cropMeasure` in `src/practice-view.ts` clones genuine prepared system ink into one SVG per measure. Its viewBox includes per-edge air; authored barline ownership already distinguishes ending separators from start repeats.
- `PracticeBrowser.render` creates separate measure wrappers. `fitLeafPreview` tightens each crop independently and switches to two rows below a width ratio. Current styles add a four-pixel preview gap.
- `PracticeView.paintScore` uses four grid cells, a passage-wide scale, independent crop origins, and centered per-measure SVGs. Equal cell heights do not establish a common staff coordinate frame or connect the staff between cells.
- Duration ownership covers `.janko-stem` and flag-axis metadata, but the pinned engine serializes hollow stems as `.janko-hollow-stem` rectangles and ordinary long-duration rings as `.janko-stem-ring`. Rectangles need their actual center/attachment geometry; the existing line-only `x1/y1` mapper cannot simply be applied to them.
- Seats carry source owner IDs, including shared heads and continuation seats. Prepared reading-head groups also retain source ownership metadata; duration serialization does not universally include it. Some ordinary/secondary stems are paths rather than lines.
- `PracticeSlots` controls fixed positions and protects unmatched attacks and active holds. It can display 5, 2, 3, 4 while cycling a joined run. `PracticeSession.visibleGroups` supplies group visibility and restores the displayed groups on ordinary Pause.
- `test/practice-attainment.test.ts` and `test/practice.test.ts` explicitly preserve readable unmeasured source music without inventing observed attacks. The older rollback's timed-clearing observation concerns a different runtime and is not a mandate to change this source contract.

Both Conventional piano and Jankó four-row use supported prepared presentations; keyboard choice is separate from fingering annotations/replacement. The ISO submodule remains the shared notation/model/calculator owner at its documented pin.

## Goals / Non-Goals

**Goals:** One application passage compositor, source-correct structural joins, reliable ownership for complete painted note geometry, and predictable coordinates for every surviving active position. Selector and active surfaces have natural centered placement with outer breathing room. One shared Options menu puts practice controls first in practice, with a configurable binding, consistent naming, compact units, separated focusable controls, and a 1% fresh-state increase. Practice range context appears once outside unnumbered notation; three stable browser columns expose joined components and their readable previews beside one short overall progress summary. Visual reproduction must test the renderer and the lifecycle together.

**Non-Goals:** Changing assessment clocks or eligibility, introducing automatic unmeasured note removal, redesigning passage navigation, regenerating stored packages, duplicating shared engraving, advancing the ISO pin, or adapting/dispatching the native release lane. Agreement with the fixed-position concept does not certify its current implementation.

## Decisions

### 1. Compose a passage in one SVG coordinate frame

Introduce a scoped viewer passage helper consumed by the browser and active view. Extract admitted measure intervals from prepared source systems while retaining source note geometry, boundary type, structural lane/reference identity, owner bindings, and source-to-display transforms. Use one outer SVG with namespaced clips/IDs and transformed content groups. Keep styles/definitions and painter order compatible with the frozen source.

Align source systems by their musical staff/reference coordinates. Determine the common vertical extent from the complete admitted passage ink, including long stems, relations, and finger annotations, before visibility changes. Independently tightened crop tops must not determine individual staff placement. If source frames cannot be mapped without changing musical meaning, report the specific unsupported passage instead of inventing a staff alignment.

Original-system ties and slurs require passage-aware projection. An actual private source repeats one slur identity across separate systems with differently placed tipped continuation ends; aligning the staff cannot join those original fragments. Canonical active padding can also separate parts of a bow that originally occupied one system. Isolate source-identified relation paint into one passage layer, deduplicate original same-system bows, and recompute their displayed paths through the pinned shared curve machinery using verified source endpoints, side, thickness, and clearance evidence. Join only the same authored relation across genuinely consecutive displayed measures; distinct source slurs remain distinct and nonconsecutive slot wraps do not create connections. Endpoint or continuation admission must be explicit, never a nearest-note guess.

Determine complete relation bounds and white reservations before fitting or hiding notes. Preserve painter order against structural rules and note ink, and give each projected relation one complete contributor registry and visibility decision. Reuse these paths for ordinary Pause restoration. Notes, source-owner identities, annotations, and reading-reference transforms remain fixed; only transient displayed relation geometry follows the composed passage. Prepared package pages, recipe authority, shared source pin, and calculator routes remain unchanged.

The October 9 native check found two remaining generic relation defects: whole-score endpoint validation let an unrelated later tie block measures 1–4, and a legitimate three-component hold had a below outgoing fragment and an above incoming fragment at an original system break. Retained original editions reproduced both faults; they are not transposition regressions. Cache raw source identities and timing separately from geometry. Before decoding contours or resolving endpoints, select relations intersecting the union of actual displayed consecutive runs, rather than their minimum/maximum envelope; preserve carry-in/out intersections. Never cache an earlier successful range as admission of another range.

Opposite-side reconciliation applies only to a verified tie component spanning distinct source systems/pages with consistent source owner, component head identities and timing metadata. Selected known tie components must retain literal source tick attributes matching the written chain, including same-sided ties; authoritative range selection precedes this check so unrelated stale metadata cannot block another leaf. Bind endpoint heads to the pinned engine's declared component plan. When optional head wrappers are absent, lazily replay the admitted historical recipe and bind its exact glyph geometry and owner set to retained paint, caching only that immutable package's ledger; do not infer identity from proximity.

Retain both original endpoint offsets and sides as separately recorded source truth. For each of the two authored-side candidates, retain each endpoint's x coordinate, and derive its y tip on the common bow side from the union of its verified owned head mask and actual text enclosure, plus that endpoint's own original mask-to-tip air. This narrowly repositions relation tips, never the frozen heads, staff or internal note spacing. Original Conventional measure 19 demonstrates why using both literal opposing-side y offsets can exhaust clearance. Build both candidates with the pinned shared contour and full note, annotation and settled-relation clearance. Any further vertical translation is bounded by half the smaller endpoint font size. Choose the admitted candidate with least total displacement from both original endpoint y offsets; a deterministic destination-side tie-break applies. Retain one complete owner/lifetime and truthful candidate metadata. Same-system contradictions, ambiguous or malformed relevant geometry and exhausted clearance still refuse. Valid same-side historical projection remains unchanged. Free view, active ties, cue generation, repeat restoration and refills consume the same admitted result. No prepared page, source identity, protected measure placement or held-note assessment changes.

The complete cue reservation exposed a conservative refill-search false negative: its compact estimate reserves three possible breaks even when a consecutive arrangement needs fewer. If that estimate exceeds the permitted upper width, still attempt the permitted upper candidate through the unchanged exhaustive state/transition checker. Keep every placement inequality, cue/edge/break reservation, protected current interval and existing analytic-certificate precondition. A successful exact certificate admits the candidate; an infeasible readable limit still refuses. This is a search correction, not relaxed fit or a new reflow policy.

Join structural staff rules using their accepted source styles and lane identities. Assign each internal separator to one source side; preserve repeat dots, start/end repeats, existing final rules, other authored boundary ink, and relation continuations. A strip's ordinary outer right edge remains open; do not manufacture a closing rule for the fourth displayed measure. When source systems omit an ordinary edge rule because of the original line break, compose that rule from admitted source style and boundary identity only at an internal consecutive join. Explicit repeat and final boundaries retain their meaning even at the strip edge. The import model retains a double-barline value, but the pinned renderer does not paint a distinct double rule; adding that engraving feature is outside this repair. Remove duplicated crop-edge structure and per-measure exterior padding at consecutive joins. Preserve genuinely required source spacing. Extending admitted structural rules through fixed-position padding is application composition, not a new note engraving recipe.

Alternative: remove the CSS gap and align the existing SVG boxes. This leaves independent vertical origins, source-system seams, per-edge air, duplicate structure, and ownership spread across view-specific implementations. A whole-work re-engraving path would couple practice to generation and exclude frozen packages without supported recipes.

### 2. Give the compositor two explicit placement policies

Leaf selection uses compact consecutive placement based on admitted measure widths and one complete passage bounding box. Fit all original leaf measures together in one strip, including genuine five-measure leaves; remove the automatic two-row threshold and use available width efficiently. Reserve a substantial, consistent left inset in logical display coordinates, accounting for it during fitting so the first notation has breathing room without changing relative note geometry or producing horizontal overflow. Observe this spacing with Schumann and a private score, including rotated/resized previews.

Reserve three stable browser columns at an unchanged viewport: compact joined/leaf ranges on the left, compact original groups in the middle, and selected-group notation on the right. Keep range and percentage spacing compact and the overall heading explicit (Total progress); neither a long header nor selecting a joined range should widen the lists and displace the preview. Anchor each row's percentage at the right, keep its measure range unwrapped, and reserve both list widths from the full score's maximum measure-number digits rather than the current selection, including three-digit endpoints. Keep a single roomier row height and padding across both lists and completed/unfinished sections, with the text vertically centered in its highlight/focus box. Format human range dashes with consistent air in the existing font, independently of the unchanged saved ID. Remove the visible joined arrow while keeping accessible component identity. Align the first entries and text baselines of both lists, keeping the middle column's group identity accessible without a visible heading that pushes its first row down. A 1–12 joined selection exposes its original groups in the middle; Right enters the component list, Up/Down browses it, and Left returns to the range list. Present only original leaves in that middle list rather than nested joined-history entries, without changing the retained tree, history, progress or reconciliation algorithms. A leaf exposes its single original-group row with the same Right/Left navigation. Selecting a component renders its complete original leaf in the right pane. Enter on a joined parent still starts that full joined range; Enter on a component starts that component. A parent-only selection identifies the whole range and its practice action, with the original groups available beside it; draw no white placeholder or oversized instruction in the preview area until a leaf is selected. Keep narrow viewport behavior accessible and previews without horizontal overflow. Do not add preview pagination or render an entire multi-page work as a miniature.

Automatic progression may still recommend a retained nested joined range, such as 1–8 within a larger frontier. Represent that selected recommendation as a transient left-column range with its own action and original middle-column leaves, rather than storing an invisible joined entry as a leaf component or silently selecting a different passage. Ordinary frontier selection removes that transient context. Keep long left/middle lists vertically bounded and make late keyboard selections visible inside their list without moving the notation pane out of view. The change intentionally presents original leaf groups in the middle; historical joined data remains intact but is not flattened into that leaf list.

Active practice uses a canonical four-position track computed from the entire selected passage and current viewport. Fix position offsets, shared staff frame, and scale before the run; reserve enough width/height for every admitted source measure. Frame the complete admitted notation naturally with substantial balanced outer space, including a clear left inset; centering an SVG's unused last-slot reservation or asymmetric exterior air alone can still leave its music visibly left-heavy. Inspect actual painted extents in the private score's bars 30–33 active and 25–29 selector. Determine placement before visibility changes and retain it across refills so hiding/replacing notes does not recenter the passage. Individual source content has a stable transform in its assigned position. Continue staff across consecutive positions, including necessary structural padding, without moving surviving note ink when a different measure refills another position.

The prerequisite consumes `PracticeSlots`; the reviewed refill follow-up supersedes its live allocation and Free view framing assumptions. Remove visible per-measure numbers from practice strips while preserving accessible source identities and the full-score renderer's measure numbers. Selection identifies its range outside the preview; the active header identifies the selected passage once. A spatial wrap keeps continuous staff and source-owned separators; relation ownership prevents false connections. The later reuse-cleared-practice-space change supplies live pinned allocation and centered consecutive Free view windows stepping two. Resize/rotation can refit the surface but must retain session, clock, progress, and input state. A moving playhead remains permitted; the score reference itself stays fixed during a run.

Alternative: compact active layout on every refill or continuously scroll a strip. Both would move the remaining reading reference. Keep compact fitting specific to preview and explicit surface layout changes.

### 3. Bind complete painted ink before composing or hiding it

Centralize the application ownership adapter and retain direct element references with complete source-owner/group bindings after transforms. Prefer verified source metadata. For the pinned frozen SVG families lacking metadata, use shape-aware geometry and source seat/slot identity: hollow rectangle center and attachment/end coordinates, ring center, flag axes, and ordinary line/path geometry. Reject ambiguous or missing ownership rather than selecting an arbitrary nearby note. No score title/ID exception is allowed.

Inventory the actual admitted note families: reading heads and their knockouts, ordinary/path/hollow stems and rings, flags and dots, shared beam paint, and passage-projected source-owned ties/slurs with their reservations. A hollow rectangle's white fill and rim share one visibility decision. Preserve source grouping/painter order; shared geometry must retain every contributing owner and any ink required by owners that remain visible. Apply each passage relation's decision once rather than allowing per-measure copies to override each other. Staff, rests, and independent structural rules stay outside note visibility. Continuation/carry-in displays retain their original owners.

Use the session's existing visibility rules for removal, error context, and ordinary Pause restoration. Reuse the registry on every paint without losing bindings or recalculating fit from the remaining visible ink. Update finger labels/contact/error feedback and playhead coordinates through the same source-to-display transforms.

Alternative: add only a selector for hollow stems. This would neither map rectangle geometry through the line-only mapper nor cover other admitted duration forms, shared owners, reservations, or composition transforms. Reconstructing a complete InkScene from arbitrary frozen packages would require source-generation authority that those packages do not all provide.

## Risks / Trade-offs

- Different source-system register/reference frames or painter orders -> admit and test an explicit common musical mapping; preserve source layering and refuse unsupported mappings clearly.
- White reservations, shared beams, and relations outlive a hidden head -> bind complete glyph families and contributors; observe exposed staff and surviving voices through removal and restoration.
- Canonical active width uses the widest passage measure -> preview keeps compact widths; inspect active readability using complete ink bounds rather than shrinking from page-sized whitespace. A read-only investigation of width: source widths range from 88.10–139.08 units in Schumann and 66.25–143.73 in a private score. Reserving per-position maxima would recover only about 2% in their long measured joined runs, while unequal widths within an unchanged four-bar leaf could recover 19.2% in the private score's bars 30–33 when width limits the fit. Four-measure batch turns are rejected because incoming music must be available before the preceding music finishes. A separate adaptive-refill plan will preserve the current measure's size and position and reuse genuinely retired space, without changing internal source spacing. The current implementation already groups display gestures by hand and written measure; a long scale does not itself retain a multi-measure display group, but true held owners can cross a barline. This repair retains the current slot/advance policy; it does not implement the adaptive allocator or claim that three earlier measures are always free. These are admitted source interval widths, not minimum engraving widths or a pianist legibility threshold.
- Fixed-position wraps look consecutive despite different source order -> preserve accessible source identities and existing reading order on continuous staff; project ties/slurs only through verified source adjacency and inspect a joined run through multiple refill states.
- Tests pass while the viewer remains visually broken -> require before/after browser observations and leave private-score/native/human acceptance explicitly pending until actually observed.
- The private score package is unavailable in this repository -> generic production-fixture regression proceeds independently; private-score acceptance remains an unchecked task, with no access inferred from the source handoff.

### Free view navigation inheritance

Previous measures/Next measures are local navigation variants of the reader controls. Absent per-slot overrides follow the current main binding; a stored null explicitly unbinds that local slot. Editing the keyboard slot does not snapshot or freeze an inherited MIDI slot. Keep optional local data separate from exact main preferences and admit both effective contexts atomically against all authoritative hidden action conflicts. A conflicting edit reports its named local/main collision and changes neither value. Runtime, Test, capture and hints use the same derived admitted dictionary. No inheritance reset control or extra editor item is added in this scope. Defaults inherit; a deliberate edit creates the local override. A future way to resume inheritance is left for a separately considered interface decision. Exact shared settings continue to use their existing common preference owner.
